# Структура проекта

Мини-карта: minimap_terrain.gd — один детерминированный растр 10 px/клетку
из cells/bathymetry/деревьев; minimap_symbols.gd — плоские условные обозначения.
minimap_terrain.gdshader накладывает живую TrailWear.texture только на
terrain-layer. Рамка/метки рисуются отдельно, не тонируются этим шейдером.
API set_landmark/remove_landmark хранит реальные здания/башни и их видимость;
игровых экземпляров зданий пока нет. Враги не перечисляются всеведущим образом.
Ресурсы объединяются по областям, знаки привязаны к существующим залежам.
Q/W/E/D/F/R: один активный слот, прежний выключается с slot_toggled(false).

Уточнение HUD: skill_slots_panel — самостоятельный прямоугольный PanelContainer,
не наследник скошенного top_bar_panel. Слоты 64×64 (адаптивно 48–64), отступ
слева от дока 64 px (24 в узком окне). Клавиши Q/W/E/D/F/R и мышь переключают
взаимоисключающие постоянные состояния через slot_toggled; способностей ещё нет.
Фон маркера отряда синий #204a83/#285ca0, меч и контур белые; геометрия прежняя.
Успешные индивидуальные результаты поиска пути не рисуют круги подтверждения.

### Обновление управления и HUD — 11 сентября

связывает бойцов; unit_control_groups.gd расширяет выбор, движение и стоп
до всей группы. individual_control=false по умолчанию; true — сохранённое
индивидуальное управление для будущих специальных юнитов. Их пути не удалены.

средней позицией всех его бойцов, а не над лидером. Фон тёмно-синий,
светлая окантовка; выбранный значок выделен белым. Кольца под бойцами отключены.
Старая панель «Выбрано / Рыцари / 15 портретов / Стоп / Найти» удалена из HUD,
но команды S и пробел и служебная панель в F1 сохранены.
Численность 0 / 15 на карточках армий больше не рисуется; сведения по «!» сохранены.
Слева от центрального дока skill_slots_panel.gd: 6 квадратов 44×44 на
тёмной подложке в стиле верхнего HUD. Клавиши слева направо Q W E D F R
(physical_keycode, работают и с русской раскладкой). Клик/клавиша испускают
slot_requested(index); способностей, затрат и кулдаунов пока нет.
Клавиши заблокированы при паузе/F1; мини-карта сохраняет прежний масштаб.

и squad-control-visual.log — SQUAD_CONTROL_PASS; squad-control-hud.log —
HUD_PASS всех 9 размеров. Снимок work/squad-controls.png просмотрен.


Базовая сцена — `scenes/main.tscn`, 15 синих рыцарей, строй 5×3 с шагом 1 клетка.
`units/squad_formation.gd` задаёт общие SIZE=15/COLUMNS=5 и плотную сетку
для начального появления, регенерации и целей группового движения.
У воды/края карты ищется ближайший целый блок суши без разбрасывания бойцов.
Пути остаются индивидуальными; синхронный марш и поворот фронта не добавлены.
Боя, NPC-спарринга, обхода соседей, столкновений тел и тестового строительства нет.
Текущее простое управление временное: ЛКМ/рамка, ПКМ, Shift-очередь, S, пробел.
Его последующая замена не должна затрагивать рендеринг и генерацию мира.

| Папка | Ответственность |
| --- | --- |
| scripts/app | Сборка мира и запуск систем |
| scripts/world | Генерация, чанки, берега, деревья и края карты |
| scripts/environment | Погода, день/ночь и освещение |
| scripts/units | Состояние движения и независимое визуальное представление |
| scripts/navigation | Поиск пути по суше, без обхода юнитов |
| scripts/input | Текущее управление камерой, выделением и приказами |
| scripts/ui | Игровой HUD, адаптивная раскладка, мини-карта, меню и сетка |
| scripts/effects | Дорожки и самостоятельный эффект крови |
| scenes/units | Переиспользуемая сцена рыцаря |
| shaders | Шейдеры и общие include-файлы |
| assets | Используемые ресурсы, рыцари, их исходники и лицензии |
| tools | Сборка ресурсов актуального рыцаря |
| tests | Автоматические проверки; не игровые стенды |
| docs/systems | Технические заметки по системам |
| docs/performance, docs/screenshots | Исторические отчёты и галерея, исключены из импорта |

Зависимости: app создаёт мир/камеру/юнитов; input выдаёт приказы через диспетчер;
navigation возвращает путь, unit исполняет его, unit_visual проигрывает анимацию.
Unit3D не содержит боевых таймеров, здоровья, избегания столкновений или тестовых флагов.
ground_blood сохранён как отключённый эффект: будущая боевая система сможет
создать его и вызывать spawn_hit/spawn_death. Сейчас он не создаёт текстур и не работает.

Служебные настройки мира (карта, часы, погода, цветокоррекция) создаются
основной сценой и app/main.gd. ui/developer_tools.gd собирает их и подсказки
в одно скрытое меню с вкладками (F1, закрыть F1/Esc). Это не финальный игровой HUD.
Сторонние addons и Compositor оставлены на исходных путях, чтобы не ломать плагин.
В .godot хранится локальный кэш движка, он не входит в Git и не является исходниками.

Не менять внешнюю папку ресурсов пользователя. Не возвращать отвергнутые
боевые/навигационные прототипы без нового запроса. Контрольная точка до очистки:
`checkpoint-before-project-cleanup-20260909` (54c41c0).

## Масштаб интерфейса

`display_layout.gd` создаётся основным миром и отслеживает размер Window.
Виртуальная база canvas_items рассчитывается из текущего окна и ограниченного
масштаба (1–1.4), а не неизменно растягивается от 1280×720. 3D остаётся
в нативном разрешении; режим окна, настройки пользователя и зум камеры не меняются.
Система работает также при паузе. Начальные/минимизированные поверхности меньше
поддерживаемого минимума 960×540 пропускаются.

`game_hud._layout_hud` размещает компактные панели относительно краёв и
переносит верхние блоки при недостатке места. Внутренние Container-узлы сохраняют
размеры содержимого. Старая панель рыцарей удалена на всех размерах окна.
Глобальные координаты Control используются и для проверки кликов по HUD.

Нижняя навигация: `command_dock.gd` содержит три круглые кнопки,
`game_hud.gd` переключает взаимоисключающие панели над ними.
`building_catalog.gd` задаёт 6 категорий/7 позиций пользователя, а
`building_browser.gd` и `building_card.gd` показывают категории и готовые PNG.
Структура по Manor Lords, палитра тёмная сине-чёрная как у верхнего HUD.
Общая подложка за превью удалена; пустое пространство пропускает клики.
Карточки 128×204 с пиктограммой внизу, названия только в tooltip.
В неподвижном слоте высотой 222 face поднимается на 18 px при выборе (0.16 s),
без обводки. Hit-test учитывает текущий видимый face; голубая полоса отмечает выбор.
`menu_medallion.gd` рисует три плоские кнопки (56 UI px), без фасок/теней.
Общий акцент нижнего меню — холодный голубой #82bfd6 вместо золотого.
`menu_surface.gdshader` больше не подключён; зерна и screen blur нет.
Превью в `assets/ui/buildings` — цельные imagegen-изображения здания с окружением
на основе BLU-рендеров Settlement_Pack (промпты и происхождение рядом).
Крепостные стены — крупный план fortress_walls_closeup.png на основе превью Original.glb Daniel Vicente,
лицензия CC BY 4.0 и промпт сохранены в FORTRESS_WALLS.md рядом с PNG.
Нет генерации превью во время игры, размещения зданий, выдуманных цен или доходов.
На узких окнах панели сдвигаются влево от мини-карты; док остаётся по центру.

«Армии»: `army_catalog.gd` хранит пять типов, `army_browser.gd` — до шести
заявок на отряды за текущую сессию, выбор и удаление заявки. Добавление через
«+» открывает выбор типа; `army_card.gd` показывает оригинальные синие портреты.
Переход в нижний ряд анимирован отдельной mouse-ignore копией карточки.
Заявки хранят state=planned отдельно от UI selection: серый портрет,
«!» и красная численность. Шейдер army_readiness меняет RGB без маски/изменения
альфы; выбор заявки не означает формирование или получение ресурсов.
Нижний ряд центрируется по ширине только воинов, плюс вынесен справа за ряд;
пустой плюс — по центру. Выбор не меняет вертикальную позицию карточки.
ПКМ на добавленной карточке удаляет именно её, обе фазы клика поглощаются.
Общий фон, правая панель с крестиком и нижний счётчик удалены. «+» рисуется
линиями без подложки (72 px hitbox); карточки — нейтральные тёмно-серые.
Портреты *_cutout.png имеют настоящую альфу и рисуются выше верхней границы
знамени, без маски на голове/оружии. Старые непрозрачные PNG сохранены.
Новая рамка army_card: задняя панель с наклонными плечами и отдельный
передний слой с фигурной табличкой. Эмблемы и их шестигранные рамки
убраны с карточек обоих рядов; PNG сохранены для будущих маркеров над отрядами.
Тёмная основа, бело-серые контуры; никаких золотых линий/имитации фасок.
Каталог head_y хранит макушку в UV исходного портрета: crown-to-waist
нормализация задаёт одинаковый рост независимо от длины оружия. Пика
выходит выше слота; раскладка резервирует вертикальный зазор для неё.
Численность согласована: 15 на каждый тип, заявки показывают 0 / 15.
Цены пока не согласованы (пустой словарь = неизвестно, не бесплатно).
Hover-tooltip убран. Контрастная кнопка army_warning_button 34×34 открывает
army_details_panel над карточкой: имя/эмблема, бойцы и ресурсы доступно/нужно.
Повторный клик или клик снаружи закрывает панель; скрытие раздела/удаление
заявки тоже закрывает её. Поля неизвестных цен не выдают бесплатное оснащение.
Пять отдельных imagegen-эмблем в army_emblems сохранены (256 px + mipmaps),
но в army_card не рисуются. Плюсы внутри карточек убраны.
Подключение реальных requirements читает stockpile в панели без списаний; никаких
новых боевых моделей, спавна, сохранения или экономики этим UI не добавляется.
Старая панель выбранных рыцарей видна при закрытых разделах дока.

Мини-карта — исключение из компактного масштаба: её сторона составляет 28%
высоты окна с нижним пределом 220 UI px и верхним 640 физических px.
Доступное место рядом с отрядом ограничивает размер, не нарушая квадратные
пропорции. В resize меняются только геометрия Control и проекции: кеш рельефа
не пересоздаётся, глобальный масштаб применяется ровно один раз.

Основа подхода: [масштабирование Godot](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)
и [Control anchors](https://docs.godotengine.org/en/stable/tutorials/ui/size_and_anchors.html).
Ограниченный рост масштаба и точки перестроения — выбор для нашего RTS HUD.
